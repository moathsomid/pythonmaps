CI/CD — التسليم المستمر مع GitHub Actions

اختبار وبناء ونشر تطبيقك تلقائياً مع كل push

← العودة إلى الرئيسية

CI (Continuous Integration): كل تعديل في الكود يُختبَر تلقائياً — اختبارات، فحص جودة، وبناء. CD (Continuous Delivery/Deployment): النشر التلقائي للبيئة أو الإنتاج بعد نجاح الاختبارات. GitHub Actions ينفّذ كل هذا داخل مستودعك: اكتب سير عمل (Workflow) وأرفقه، والباقي تلقائي.

الفائدة: أخطاء تُكتشف قبل أن تصل للمستخدم، وكل commit أصبح شحنة جاهزة للنشر. توقف عن "يعمل عندي" — البيئة أصبحت موحدة وموثقة.

1. بنية الـ Workflow

ملف YAML في مجلد .github/workflows/. المفاهيم: Workflow (سير العمل)، Job (مهمة تعمل على بيئة)، Step (خطوة داخل المهمة)، Trigger (متى يعمل).

# .github/workflows/ci.yml name: CI on: push: branches: [ main ] pull_request: jobs: test: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-python@v5 with: python-version: '3.11' - run: pip install -r requirements-dev.txt - run: ruff check . # فحص الجودة - run: pytest --cov=app # الاختبارات
🔍 كيف يعمل؟ on.push يطلق السير عند كل push إلى main. uses: يجلب خطوات جاهزة (checkout يجلب الكود، setup-python يهيئ بايثون). لو فشلت أي خطوة، يفشل السير وتظهر علامة حمراء في الـ PR.

2. بناء المصفوفات (Matrix Builds)

اختبر على عدة إصدارات بايثون ونظم تشغيل في وقت واحد — ضمان أن كودك يعمل في كل مكان.

jobs: test: runs-on: ubuntu-latest strategy: matrix: python-version: ['3.10', '3.11', '3.12'] steps: - uses: actions/checkout@v4 - uses: actions/setup-python@v5 with: python-version: ${{ matrix.python-version }} - run: pip install -r requirements.txt - run: pytest

3. الأسرار (Secrets)

كلمات المرور ومفاتيح API لا توضع في الكود إطلاقاً. أضفها في Settings ← Secrets، واستدعِها في السير.

steps: - run: "docker build -t myapp . --build-arg API_KEY=${{ secrets.API_KEY }}"
⚠️ لا تكشف الأسرار: لا تطبع secrets.* في echo أو logs. GitHub يمنع نشرها في الـ logs لكن لا تعتمد على ذلك — عاملها بحذر.

4. التخزين المؤقت والملفات (Caching + Artifacts)

الـ caching يسرّع السير (لا تعيد تنزيل المكتبات كل مرة)، والـ artifacts تحفظ نواتج البناء (صور، تقارير) لتنزيلها أو تمريرها لاحقاً.

steps: - uses: actions/setup-python@v5 with: python-version: '3.11' cache: pip # تفعيل التخزين المؤقت تلقائياً - run: pip install -r requirements.txt - run: pytest - uses: actions/upload-artifact@v4 with: name: coverage-report path: htmlcov/

5. النشر التلقائي (CD)

بعد نجاح الاختبارات، انشر على السيرفر. أبسط الطرق: SSH إلى السيرفر ونشر الـ Docker image أو سحب الكود وتشغيله.

name: Deploy on: push: branches: [ main ] jobs: deploy: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - name: Build Docker image run: docker build -t myapp . - name: Deploy via SSH uses: appleboy/ssh-action@v1.0.3 with: host: ${{ secrets.HOST }} username: ${{ secrets.USER }} key: ${{ secrets.SSH_KEY }} script: | cd /app git pull docker compose up -d --build
💡 بيئات الإنتاج: استخدم environments في GitHub لتفصل الأسرار والقواعد بين staging و production — النشر للإنتاج فقط بعد موافقة يدوية إن شئت.

6. التمارين

تمرين 1: CI أساسي
أضف سير عمل لمشروعك: ruff + pytest مع 3 إصدارات بايثون في مصفوفة.
تمرين 2: بناء Docker
أضف خطوة تبني الـ Docker image وتحمّلها إلى Docker Hub أو GHCR.
تمرين 3: CD كامل
أنشئ سير عمل ينشر تلقائياً على سيرفر عند كل push إلى main — مع تراجع (rollback) يدوي إن لزم.

📝 ملخص CI/CD

  • Workflow: ملف YAML يصف الأتمتة
  • Matrix: اختبار عبر عدة إصدارات
  • Secrets: أسرار منفصلة وآمنة عن الكود
  • Caching/Artifacts: تسريع وحفظ نواتج البناء
  • CD: نشر تلقائي عبر SSH بعد نجاح الاختبارات
