أنظمة Multi-Agent

الأسابيع 57-60: من Agent واحد إلى فريق وكلاء يتعاونون — أنماط، تنسيق، ذاكرة طويلة المدى، وتواصل

← العودة إلى الرئيسية

بعد أن أتقنت بناء Agent واحد، حان وقت القفزة الحقيقية: أنظمة Multi-Agent حيث يتعاون عدة وكلاء كلٌّ في تخصصه لتنفيذ مهام معقدة. هذا هو الفرق بين تطبيق AI بسيط ونظام AI متكامل يحل مشاكل حقيقية.

🎯 لماذا Multi-Agent؟ وكيل واحد يملك معرفة عامة لكنه ضعيف في التخصص. فريق وكلاء = تخصص لكل وكيل + تقسيم المهام + مراجعة النتائج. النتائج أدق بكثير.

1. متى تحتاج Multi-Agent؟

ليس كل شيء يحتاج فريق وكلاء. القاعدة الذهبية: ابدأ بوكيل واحد، وأضف وكلاء فقط عندما يكون هناك تقسيم طبيعي للمهام.

  • نعم: بحث علمي (جمع + تحليل + مراجعة)، كود معقد (كتابة + مراجعة + اختبار)، محادثة متعددة التخصصات
  • لا: أسئلة عامة، مهمة واحدة بسيطة، عندما يزيد التواصل عن المهمة نفسها

2. أنماط Multi-Agent الشهيرة

  • Supervisor / Orchestrator: وكيل رئيسي يوزع المهام على وكلاء متخصصين (الأكثر شيوعاً)
  • Pipeline / Chain: كل وكيل يمرر ناتجه للوكيل التالي (جمع → تحليل → تقرير)
  • Hierarchy: وكلاء تحت وكلاء — تنسيق متعدد المستويات
  • Swarm / Collaborative: وكلاء متساوون يتشاركون الحالة ويتعاونون بحرية
  • Debate / Critique: وكلاء يناقشون ويقيّمون إجابات بعضهم (يرفع الجودة)

3. التنسيق مع LangGraph

LangGraph هو الخيار الأمثل لأنظمة Multi-Agent لأنه يدير الحالة المشتركة والتدفق الشرطي بشكل صريح.

# تنسيق: Supervisor يوزع على Research و Writer from langgraph.graph import StateGraph, END import operator from typing import TypedDict, list class State(TypedDict): task: str research: str report: str def supervisor(state): return {"task": "اجمع المعلومات عن سوق السيارات الكهربائية"} def researcher(state): # وكيل متخصص في البحث return {"research": "سوق السيارات الكهربائية نما 40% في 2025..."} def writer(state): # وكيل متخصص في الكتابة return {"report": f"تقرير مبني على: {state['research']}"} graph = StateGraph(State) graph.add_node("supervisor", supervisor) graph.add_node("researcher", researcher) graph.add_node("writer", writer) graph.set_entry_point("supervisor") graph.add_edge("supervisor", "researcher") graph.add_edge("researcher", "writer") graph.add_edge("writer", END) app = graph.compile()
💡 المفتاح: الحالة المشتركة (state) هي ما يجعل الوكلاء "يتواصلون". كل وكيل يقرأ ما كتبه السابق ويضيف عليه.

4. التوجيه الشرطي (Conditional Routing)

أقوى ميزة: القرار بين الوكلاء يُتخذ ديناميكياً حسب الحالة — مثل مسار إنساني حقيقي.

def router(state): # لو الطلب عن كود → Coding Agent، لو بحث → Research Agent if "كود" in state["task"] or "برمج" in state["task"]: return "coding" if "حلل" in state["task"] or "ابحث" in state["task"]: return "research" return "general" graph.add_conditional_edges("supervisor", router, {"coding": "coding_agent", "research": "researcher", "general": "general_agent"})

5. الذاكرة طويلة المدى (Long-term Memory)

الوكلاء بحاجة لذاكرة تتجاوز الجلسة الواحدة: تفضيلات المستخدم، تاريخ المهام، معرفة متراكمة.

  • Qdrant / Vector DB: تخزين الذكريات كمتجهات واسترجاع الأهم عند الحاجة
  • Redis: ذاكرة جلسة سريعة (session state)
  • PostgreSQL: تاريخ دائم وموثوق للذكريات المهمة
# نموذج ذاكرة بسيط مع Qdrant from qdrant_client import QdrantClient client = QdrantClient(url="http://localhost:6333") def save_memory(user_id, text, embedding): client.upsert( collection_name="memories", points=[{ "id": hash(text), "vector": embedding, "payload": {"user_id": user_id, "text": text, "time": time.time()} }]) def recall(query_embedding, user_id, top=5): hits = client.search(collection_name="memories", query_vector=query_embedding, query_filter={"must": [{"key": "user_id", "match": {"value": user_id}}]}, limit=top) return [h.payload["text"] for h in hits]

6. تواصل الوكلاء (Agent Communication)

طرق التواصل بين الوكلاء:

  • عبر الحالة (state): الأكثر استخداماً في LangGraph — بسيط وموثوق
  • عبر الرسائل (message passing): وكلاء يرسلون رسائل مباشرة لبعضهم
  • عبر الأحداث (events/queues): Redis Pub/Sub أو Celery — تدفق غير متزامن
⚠️ خطأ شائع: تسمية كل Agent جديد دون داعٍ حقيقي. الوكيل الواحد المزوّد بأدوات (tools) جيدة أحياناً أفضل من 3 وكلاء يتواصلون بطيئاً.

7. التمارين

تمرين 1: Supervisor + 2 وكلاء
ابنِ نظاماً: وكيل Research يجمع، ووكيل Writer يكتب تقريراً، وSupervisor يوجّه. شغّله على موضوع تحبه.
تمرين 2: توجيه شرطي
أضف router يفصل: طلبات الكود → coding agent، طلبات البحث → research agent.
تمرين 3: ذاكرة طويلة المدى
أضف Qdrant لحفظ تفضيلات المستخدم واسترجاعها في المحادثات التالية.

📝 ملخص أنظمة Multi-Agent

  • أنماط: Supervisor، Pipeline، Hierarchy، Swarm، Debate
  • LangGraph يدير الحالة والتوجيه الشرطي والتدفق
  • ذاكرة طويلة المدى عبر Qdrant/Redis/PostgreSQL
  • القاعدة: ابدأ بوكيل واحد وأضف فقط عند الحاجة الحقيقية
