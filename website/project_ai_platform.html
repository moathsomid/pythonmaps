AI Platform Deployment — نشر منصة ذكاء اصطناعي

منصة أسئلة وأجوبة على مستنداتك: RAG + FastAPI + Docker + CI/CD + AWS — من الفكرة إلى الإنتاج

← العودة إلى الرئيسية

هذا المشروع يجمع كل ما تعلمته في السنة الأولى: Python وFastAPI وPostgreSQL وDocker وRAG وQdrant وCI/CD وAWS. الهدف: منصة ترفع مستنداً، تفهرس محتواه، ثم تجيب عن الأسئلة منه — مشغلة على الإنترنت ببنية تحتية حقيقية.

🎯 القياس النهائي: منصة تعمل بـ domain حقيقي + HTTPS، ترفع 50 مستنداً، وتجيب بدقة لا تقل عن 85% حسب تقييم RAGAS، مع CI/CD ينشر تلقائياً.

1. المعمارية الكاملة

  • FastAPI: واجهة API (رفع المستندات، الدردشة، الإدارة)
  • Qdrant: تخزين المتجهات والبحث
  • PostgreSQL: بيانات المستخدمين والمستندات
  • Redis: تخزين مؤقت وجلسات ومهام خلفية
  • Docker Compose: تشغيل كل الخدمات معاً
  • GitHub Actions: CI/CD تلقائي
  • AWS EC2: الاستضافة + Nginx + SSL

2. واجهة API (FastAPI)

# app/main.py from fastapi import FastAPI, UploadFile from app.services import indexing, qa app = FastAPI(title="AI Platform") @app.post("/documents") async def upload_document(file: UploadFile): # 1) قراءة وحفظ الملف # 2) تقسيم + تضمين (chunk + embed) # 3) تخزين في Qdrant + تسجيل في PostgreSQL return await indexing.ingest(file) @app.post("/chat") async def chat(question: str): # 1) استرجاع الأجزاء ذات الصلة من Qdrant # 2) توليد الإجابة من النموذج return await qa.answer(question) @app.get("/health") def health(): return {"status": "ok"}

3. Docker Compose

# docker-compose.yml services: api: build: . ports: - "8000:8000" depends_on: [db, qdrant, redis] environment: DATABASE_URL: postgresql://user:pass@db:5432/app QDRANT_URL: http://qdrant:6333 REDIS_URL: redis://redis:6379/0 db: image: postgres:15 environment: POSTGRES_USER: user POSTGRES_PASSWORD: pass POSTGRES_DB: app volumes: [pg_data:/var/lib/postgresql/data] qdrant: image: qdrant/qdrant volumes: [qdrant_data:/qdrant/storage] redis: image: redis:7-alpine volumes: pg_data: qdrant_data:
🔍 كيف يعمل؟ docker compose up -d يشغّل كل الخدمات. التطبيق يتصل بقاعدة البيانات و Qdrant و Redis بأسمائها الداخلية (db, qdrant, redis). البيانات محفوظة في volumes فلا تضيع عند إعادة التشغيل.

4. CI/CD pipeline

# .github/workflows/deploy.yml name: Test + Deploy on: push: branches: [ main ] jobs: test: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-python@v5 with: { python-version: '3.11', cache: pip } - run: pip install -r requirements-dev.txt - run: ruff check . - run: pytest --cov=app deploy: needs: test runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: appleboy/ssh-action@v1.0.3 with: host: ${{ secrets.HOST }} username: ${{ secrets.USER }} key: ${{ secrets.SSH_KEY }} script: | cd /opt/ai-platform git pull docker compose up -d --build docker compose exec api alembic upgrade head

5. النشر على AWS EC2

# على الخادم (بعد تثبيت Docker و git) git clone https://github.com/you/ai-platform.git /opt/ai-platform cd /opt/ai-platform docker compose up -d --build # Nginx كـ reverse proxy مع SSL مجاني sudo apt install nginx certbot python3-certbot-nginx sudo certbot --nginx -d ai.example.com
⚠️ قبل الإطلاق: أغلق منافذ 8000 على الإنترنت في الـ Security Group (يتكفل Nginx بـ 80/443). استخدم HTTPS إجبارياً، وضع الأسرار في env للخادم لا في الكود.

6. المراقبة والقياس

  • Health check: endpoint /health يراقبه Docker تلقائياً
  • سجلات منظمة: structlog مع JSON للبحث السهل
  • مقاييس: زمن الاستجابة، معدل الأخطاء، عدد الطلبات
  • تقييم RAG: جولة RAGAS أسبوعية لمراقبة جودة الإجابات
