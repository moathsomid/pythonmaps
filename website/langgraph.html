LangGraph — الرسوم البيانية للوكلاء

تحكم دقيق في تدفق الوكيل: Nodes, Edges, حالة مشتركة، وحلقات شرطية

← العودة إلى الرئيسية

بينما تُناسب سلاسل LangChain التدفقات الخطية، تُناسب LangGraph التدفقات المعقدة التي تحتاج حلقات وشروط وذاكرة. الفكرة: ترسم تطبيقك كرسم بياني — عُقد (Nodes) هي خطوات العمل، وأضلاع (Edges) تصلها، والحالة (State) تتنقل بينها.

لماذا رسم بياني؟ السلسلة الخطية تنفذ خطوات بالترتيب دائماً. لكن وكيلاً حقيقياً يحتاج أن يقرر: هل أعيد المحاولة؟ هل أنتقل لخطوة أخرى؟ هل أنهي؟ الرسوم البيانية تصف هذا بدقة ووضوح.

1. المكونات الأساسية

  • State: الحالة المشتركة (dict) التي تتنقل بين العقد — الرسائل، المتغيرات، النتائج
  • Node: دالة بايثون تستقبل الحالة وترجع تحديثاً لها
  • Edge: خط يصل عقدتين — يتحكم بترتيب التنفيذ
  • Conditional Edge: قرار ديناميكي — أي عقدة تالية حسب قيمة الحالة
  • Checkpointer: حفظ حالة التنفيذ لاستئنافها أو تتبع التاريخ

2. أول رسم بياني

مثال بسيط: ترحيب ← معالجة السؤال ← إجابة النموذج.

pip install langgraph langchain-openai from typing import TypedDict from langgraph.graph import StateGraph, START, END from langchain_openai import ChatOpenAI llm = ChatOpenAI(model="gpt-4o-mini") # 1) تعريف الحالة class State(TypedDict): question: str answer: str # 2) العقد (Nodes) def greet(state: State) -> dict: print("مرحباً، سأجيب عن سؤالك...") return state def answer(state: State) -> dict: response = llm.invoke(f"أجب بإيجاز: {state['question']}") return {"answer": response.content} # 3) بناء الرسم البياني builder = StateGraph(State) builder.add_node("greet", greet) builder.add_node("answer", answer) builder.add_edge(START, "greet") builder.add_edge("greet", "answer") builder.add_edge("answer", END) graph = builder.compile() result = graph.invoke({"question": "ما هو LangGraph؟"}) print(result["answer"])

3. الأضلاع الشرطية (Conditional Edges)

الخيار الأقوى: عقدة تقرر إلى أين تنتقل تبعاً للمحتوى. هذا ما يمكّن حلقة "جرب ثم راجع ثم أعد الجواب".

from langgraph.graph import StateGraph, START, END def check_quality(state: State) -> str: # إرجاع اسم العقدة التالية if "لا أعرف" in state["answer"]: return "improve" return "finalize" builder = StateGraph(State) builder.add_node("answer", answer) builder.add_node("improve", improve) builder.add_node("finalize", finalize) builder.add_edge(START, "answer") builder.add_conditional_edges("answer", check_quality, { "improve": "improve", "finalize": "finalize", }) builder.add_edge("improve", "answer") # حلقة: عُد وحسّن ثم أجب مجدداً builder.add_edge("finalize", END)
🔍 كيف يعمل؟ دالة القرار ترجع اسم العقدة التالية، والخريطة تحدد الانتقال. بفضل الحلقة (improve → answer) يمكن للوكيل تحسين إجابته حتى ترضيك — تماماً مثل الإنسان.

4. الحفظ والاستئناف (Checkpointing)

مع MemorySaver أو قاعدة بيانات، يحفظ LangGraph حالة كل تنفيذ تحت معرّف thread. هذا يتيح: محادثات متعددة، استئناف بعد انقطاع، وتاريخ كامل للتدقيق.

from langgraph.checkpoint.memory import MemorySaver checkpointer = MemorySaver() graph = builder.compile(checkpointer=checkpointer) # كل محادثة لها thread_id خاص — حالة مستقلة config = {"configurable": {"thread_id": "user-42"}} result1 = graph.invoke({"question": "اذكر اسمي أحمد"}, config) result2 = graph.invoke({"question": "ما اسمي؟"}, config) # يتذكر

5. البث والمراقبة (Streaming)

لمحادثة تفاعلية، بثّ أحداث كل عقدة أو رموز الإجابة ليراها المستخدم لحظة بلحظة.

for event in graph.stream({"question": "اشرح langgraph"}, config=config): for key, value in event.items(): print(f"العقدة {key}: {value}") # كل خطوة تظهر مباشرة

6. التمارين

تمرين 1: تدفق بسيط
ابنِ رسم بياني: استقبال سؤال ← استرجاع سياق ← إجابة ← تلخيص.
تمرين 2: حلقة جودة
أضف عقدة تراجع تُحسّن الإجابة وتعيد المحاولة مرتين كحد أقصى.
تمرين 3: محادثات متعددة
شغّل محادثتين بمستخدمين مختلفين (thread_ids مختلفة) وتأكد من عدم تداخل الذاكرة.

📝 ملخص LangGraph

  • StateGraph: رسم بياني للوكلاء — عقد وأضلاع
  • Nodes: دوال بايثون تعالج الحالة وترجع تحديثاً
  • Conditional Edges: قرارات ديناميكية وحلقات
  • Checkpointing: حفظ الحالة واستئنافها لكل مستخدم
  • Streaming: مراقبة خطوات التنفيذ لحظة بلحظة
