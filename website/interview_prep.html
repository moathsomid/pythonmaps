← العودة إلى الرئيسية

المقابلة التقنية تُقيّم ثلاث مهارات: حل المشاكل (كود)، التصميم (System Design)، والمعرفة (مفاهيم AI والهندسة).

1. أسئلة الكود (Coding)

  • أتقن: قوائم، قواميس، خوارزميات أساسية، تعقيد زمني (Big-O)
  • تدرب على LeetCode/HackerRank 2-3 مسائل يومياً
  • قُل تفكيرك بصوت عالٍ أثناء الحل
  • اختبر حالات الحافة (empty، large، duplicates)
# مثال شائع: إيجاد الأكثر تكراراً from collections import Counter def most_frequent(nums, k): # O(n) — باستخدام Counter return [x for x, _ in Counter(nums).most_common(k)]

2. أسئلة System Design

سيُطلب منك تصميم نظام: "صمم نظام chat"، "صمم نظام RAG". اتّبع إطاراً:

  1. وضوح المتطلبات: من المستخدمون؟ كم الحجم؟
  2. المخطط: ارسم المكونات (API، DB، Cache، Queue، Workers)
  3. التخزين: ماذا في PostgreSQL؟ ماذا في Qdrant؟ ماذا في Redis؟
  4. التدفق: ماذا يحدث لطلب واحد من البداية للنهاية
  5. التوسع: أين الزحمة؟ وكيف تحل؟
  6. الموثوقية: ماذا لو فشلت خدمة؟

3. مفاهيم AI/ML

  • اشرح RAG: لماذا؟ مكوناته؟ كيف تقيّمه (RAGAS)؟
  • ما الفرق بين embeddings والـ tokens؟
  • ما الفرق بين fine-tuning و RAG ومتى تختار أيهما؟
  • اشرح Prompt Engineering: context، few-shot، chain-of-thought
  • ما تحديات الوكلاء: hallucination، cost، latency، memory؟
# إجابة مختصرة تصلح لمقابلة: متى RAG ومتى Fine-tuning؟ # RAG: بيانات تتغير كثيراً + تحتاج استشهادات + بدون تدريب # Fine-tune: أسلوب/صوت ثابت + تخصص عميق + بيانات تاريخية # الأفضل غالباً: RAG أولاً، ثم fine-tune عند الحاجة

4. الأسئلة السلوكية (Behavioural)

  • جهّز قصة STAR لكل مشروع: الموقف، المهمة، الفعل، النتيجة
  • "حدثني عن مشروع" → قصتك الأولى: المشكلة + حلولك + الأرقام
  • "ما أصعب خطأ" → اربطها بما تعلمته
