AWS — EC2 + S3 + IAM + VPC

الحوسبة والتخزين والصلاحيات والشبكات — أساس البنية التحتية السحابية

← العودة إلى الرئيسية

AWS أكبر مزود خدمات سحابية في العالم، والأكثر استخداماً في المنطقة العربية. لانشر تطبيقاتك تحتاج أربع خدمات أساسية: EC2 للخوادم، S3 للتخزين، IAM للصلاحيات، وVPC للشبكات.

💡 ابدأ مجاناً: AWS Free Tier يعطيك 750 ساعة EC2 شهرياً وسنة كاملة من S3 مجاناً. أنشئ حساباً وثبّت awscli وستكمل هذا الدرس عملياً.

1. EC2 — الحوسبة

EC2 (Elastic Compute Cloud) = خوادم افتراضية. كل خادم يبدأ من AMI (قالب النظام) بنوع معين (مثل t3.micro الرخيص) وضمن Security Group (جدار الحماية).

# تثبيت وتكوين AWS CLI pip install awscli aws configure # أدخل: Access Key, Secret Key, المنطقة (مثل us-east-1) # إنشاء خادم (AMI = Ubuntu 22.04) aws ec2 run-instances \ --image-id ami-04b4f1a9cf54c1d8a \ --instance-type t3.micro \ --key-name my-key \ --security-group-ids sg-xxxx # الاتصال بالخادم ssh -i my-key.pem ubuntu@<public-ip>
⚠️ الأمان: افتح فقط المنافذ الضرورية (SSH من عنوانك، 80/443 للويب) في الـ Security Group. استخدم مفتاح SSH خاص وليس كلمة مرور. لا تستخدم نوع instances ضخمة وأنت تتجرب — التكلفة.

2. S3 — التخزين

S3 (Simple Storage Service) لتخزين الملفات: صور، بيانات، نسخ احتياطية، وملفات نماذج. المخازن تسمى Buckets بأسماء عالمية فريدة.

# إنشاء مخزن aws s3 mb s3://my-app-assets-2026 # رفع ملف aws s3 cp model.joblib s3://my-app-assets-2026/models/ # مزامنة مجلد كامل aws s3 sync ./data s3://my-app-assets-2026/data # دورة حياة: نقل الملفات القديمة تلقائياً إلى Glacier (أرخص) aws s3api put-bucket-lifecycle-configuration --bucket my-app-assets-2026 \ --lifecycle-configuration file://lifecycle.json
💡 الاستخدام الشائع في مشاريع AI: تخزين الـ datasets والنماذج الكبيرة على S3، والنسخ الاحتياطي لقاعدة البيانات، وإضافة ملفات ثابتة لتطبيقك.

3. IAM — الصلاحيات

IAM (Identity and Access Management) يتحكم بمن يستطيع ماذا. القاعدة الذهبية: الأقل صلاحية (Least Privilege) — لا تعطِ أحداً أكثر مما يحتاج.

# سياسة: قراءة S3 فقط (وليس كل الحساب!) # policy.json { "Version": "2012-10-17", "Statement": [ { "Effect": "Allow", "Action": ["s3:GetObject"], "Resource": "arn:aws:s3:::my-app-assets-2026/*" } ] } # إنشاء دور وتطبيق السياسة aws iam create-role --role-name app-reader --assume-role-policy-document file://trust.json aws iam put-role-policy --role-name app-reader --policy-name read-s3 --policy-document file://policy.json
⚠️ خطأ شائع: إنشاء مستخدم root أو دور بـ "*" في كل الأماكن (admin كامل). استخدم أدوار محددة، وللتطبيقات على EC2 استخدم instance profile بدل مفاتيح مدمجة في الكود.

4. VPC — الشبكات

VPC (Virtual Private Cloud) شبكة افتراضية معزولة لحسابك. تقسّم إلى Subnets: عامة (لها إنترنت) وخاصة (بدون). الـ Security Groups والـ NACLs تتحكم بالدخول.

# الأبنية الأساسية: VPC → Subnets → Internet Gateway → Route Tables aws ec2 create-vpc --cidr-block 10.0.0.0/16 # مثال معماري بسيط # - Subnet عام: يحتوي الـ Load Balancer والـ EC2 العامة # - Subnet خاص: يحتوي قاعدة البيانات (بلا إنترنت) # - NAT Gateway: يسمح للموارد الخاصة بالخروج دون أن تُخترق
💡 لماذا نعزل؟ قاعدة البيانات في شبكة خاصة لا يمكن الوصول إليها من الإنترنت إطلاقاً — حتى لو تسرّب أحد بالمفاتيح، السطح القابل للهجوم أصغر بكثير.

5. التمارين

تمرين 1: خادم EC2
أنشئ خادم Ubuntu، ثبّت عليه Docker، وارفع فيه تطبيق FastAPI وشغّله.
تمرين 2: تخزين S3
ارفع ملفات تطبيقك إلى S3، وفعّل دورة حياة تنقل القديم لـ Glacier.
تمرين 3: سياسة IAM
أنشئ دوراً يقرأ S3 فقط واربطه بـ EC2 (instance profile) واختبر صلاحياته.

📝 ملخص AWS

  • EC2: خوادم افتراضية مع AMI + Security Groups
  • S3: تخزين ملفات لا نهائي مع دورة حياة
  • IAM: أدوار وسياسات بأقل صلاحية ممكنة
  • VPC: شبكات معزولة — عامة وخاصة
  • الأمان: افتح الحد الأدنى، استخدم أدواراً لا مفاتيح
