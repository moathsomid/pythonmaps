Message Queues — Redis و Celery

الأسبوع 62: مهام خلفية، طوابير، وتوسيع أفق أبنيتك

← العودة إلى الرئيسية

بعض المهام لا يجب أن تُنفذ أثناء الطلب مباشرة (إرسال إيميل، معالجة PDF، توليد تقرير). هنا تأتي طوابير الرسائل: تضع المهمة في الطابور، وworker يلتقطها وينفذها لاحقاً.

1. لماذا الطوابير؟

  • سرعة الاستجابة: الطلب يعود فوراً والمهمة تجري في الخلفية
  • الموثوقية: لو فشل التنفيذ، يمكن إعادة المحاولة
  • التوسع: أضف المزيد من الـ workers لتسريع المعالجة

2. Celery + Redis

Celery هو الـ task queue الأشهر في Python، وRedis هو الـ broker (وسيط الرسائل).

# tasks.py from celery import Celery from time import sleep app = Celery("tasks", broker="redis://localhost:6379/0") @app.task def send_email(to, subject, body): sleep(2) # محاكاة إرسال print(f"تم إرسال البريد إلى {to}") return {"ok": True} # تشغيل الـ worker: # celery -A tasks worker --loglevel=info
# main.py — إرسال مهمة للخلفية from tasks import send_email from fastapi import FastAPI app = FastAPI() @app.post("/subscribe") def subscribe(email: str): task = send_email.delay(email, "مرحباً", "تم الاشتراك بنجاح") return {"status": "queued", "task_id": task.id}

3. تتبع النتيجة

# result backend يخزن النتيجة لاسترجاعها لاحقاً app = Celery("tasks", broker="redis://localhost:6379/0", backend="redis://localhost:6379/1") # من الطلب: from tasks import app as celery_app @app.get("/status/{task_id}") def status(task_id: str): result = celery_app.AsyncResult(task_id) return {"state": result.state, "result": result.result}

4. Redis كطابور بسيط

لمهام أبسط أو لو أردت التحكم اليدوي، يمكنك استخدام Redis List كطابور مباشرة.

import redis r = redis.Redis() # المنتج: يضيف للمؤخرة r.rpush("queue", "process-file.pdf") # المستهلك: يلتقط من الأمام (blocking) while True: job = r.blpop("queue", timeout=0) process(job[1])
💡 Pub/Sub vs Queue: الطابور (Queue) يوصّل الرسالة لمستهلك واحد — "منفذ واحد فقط". الـ Pub/Sub يبثها لكل المشتركين — "الكل يستلم".
