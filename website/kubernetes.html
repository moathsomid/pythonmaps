Kubernetes + Helm

الأسابيع 73-76: تنسيق الحاويات، إعدادات، شبكات، ونشر منظم

← العودة إلى الرئيسية

Docker يشغّل حاوية واحدة. Kubernetes (K8s) يدير آلاف الحاويات عبر عدة خوادم: يوزع الحمل، يعيد التشغيل عند الفشل، ويوسّع تلقائياً.

1. المفاهيم الأساسية

  • Node: خادم (عامل) يشغل الحاويات
  • Pod: أصغر وحدة — حاوية (أو أكثر) بمورد مشترك
  • Deployment: يصف "كم نسخة ونأي إصدار" ويدير التحديثات
  • Service: نقطة وصول ثابتة لـ Pods (توازن الحمل داخلياً)
  • Ingress: الباب الخارجي للشبكة (راوتر للطلبات الخارجية)
  • ConfigMap / Secret: الإعدادات والأسرار

2. أول Deployment

# deployment.yaml apiVersion: apps/v1 kind: Deployment metadata: name: api spec: replicas: 3 selector: matchLabels: app: api template: metadata: labels: app: api spec: containers: - name: api image: myapp/api:1.2.0 ports: - containerPort: 8000 envFrom: - configMapRef: name: app-config
# service.yaml — توازن الحمل الداخلي apiVersion: v1 kind: Service metadata: name: api spec: selector: app: api ports: - port: 80 targetPort: 8000
# التطبيق kubectl apply -f deployment.yaml kubectl apply -f service.yaml kubectl get pods # 3 pods جاهزة kubectl scale deployment api --replicas=5 # توسيع
💡 كيف يعمل؟ الـ Deployment يضمن دائماً وجود 3 نسخ. لو مات Pod، ينشئ K8s نسخة جديدة فوراً. الـ Service يوزع الطلبات على النسخ الثلاث.

3. Ingress — البوابة الخارجية

apiVersion: networking.k8s.io/v1 kind: Ingress metadata: name: app-ingress spec: rules: - host: app.example.com http: paths: - path: / pathType: Prefix backend: service: name: api port: number: 80

4. ConfigMap و Secret

# configmap.yaml — إعدادات غير سرية apiVersion: v1 kind: ConfigMap metadata: name: app-config data: LOG_LEVEL: info MAX_WORKERS: "4" # secret.yaml — أسرار مشفرة base64 apiVersion: v1 kind: Secret metadata: name: app-secrets stringData: DATABASE_URL: postgresql://user:pass@db:5432/app
⚠️ الأمان: لا تضع الأسرار في manifest مباشرة في git. استخدم External Secrets أو Vault، أو فعّل التشفير عند التخزين.

5. Helm — تغليف التطبيقات

Helm = "مدير حزم" لـ Kubernetes. تغلف كل الـ manifests في Chart وتنشره بأمر واحد مع إعدادات قابلة للتخصيص.

# helm create myapp → هيكل جاهز myapp/ ├── Chart.yaml ├── values.yaml # القيم القابلة للتعديل ├── templates/ │ ├── deployment.yaml │ ├── service.yaml │ └── _helpers.tpl # التثبيت بأمر واحد مع القيم helm install myapp ./myapp --set replicas=5 --set image.tag=1.3.0 helm upgrade myapp ./myapp --set image.tag=1.4.0
